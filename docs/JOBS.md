# Задания, процедуры и группы

## Новый перенос в TransferData

При сохранении нового задания типа «Перенос SQL Server → PostgreSQL» обработчик
автоматически выполняет подготовку:

1. Проверяет подключения к обеим базам.
2. Получает структуру исходной таблицы.
3. Заполняет соответствие столбцов внутри задания, если оно ещё не задано.
4. Создаёт отсутствующую таблицу PostgreSQL.

Ход каждого шага виден в карточке запуска в истории и обновляется автоматически.
При ошибке следующий шаг не выполняется. Существующая таблица не изменяется.
Короткие имена столбцов сохраняются, имена длиннее 63 UTF-8 байт автоматически
сокращаются с уникальным суффиксом. Сохранённое соответствие можно проверить
и отредактировать в настройках задания. Явное соответствие пользователя сохраняется.
Подготовка не переносит строки: загрузка запускается кнопкой или расписанием.
Повтор подготовки доступен через «Другие действия → Создать таблицу».

## Процедура MS SQL Server

В TransferData создайте задание типа «Процедура MS SQL Server». Выберите
подключение, укажите отдельно схему (например, `dbo`) и имя процедуры
(например, `RefreshModels`). PostgreSQL для такого задания не нужен: его сервер
и базу в подключении можно оставить пустыми.

Входные параметры задаются JSON-объектом с именами без `@`:

```json
{"DateFrom": "2026-10-01", "FullLoad": true}
```

Поддерживаются строки, числа, логические значения и `null`; имена параметров —
латинские буквы, цифры и подчёркивания, первый символ не цифра. OUTPUT-параметры,
табличные параметры и сохранение наборов результатов не поддерживаются.
Пустой объект `{}` означает вызов без параметров. Значения передаются отдельно
от SQL-текста. Не храните пароли в параметрах: настройки доступны операторам панели.

При создании проверяется только подключение; сама процедура не вызывается.
Её можно запустить вручную с подтверждением или по обычному расписанию.
Используется существующий обработчик TransferData под Windows-учётной записью
задания планировщика. У неё должно быть разрешение EXECUTE на процедуру.
Отдельное окно PowerShell или отдельный обработчик для процедур не нужны.
Если файла PostgreSQL credentials нет, обработчик всё равно запускает процедуры.

Укажите таймаут в секундах (по умолчанию 3600). Успех — завершение всех наборов
результатов и код RETURN 0. Ненулевой код или ошибка означают неуспех, транзакция
соединения откатывается. Собственные COMMIT внутри процедуры и внешние побочные
эффекты не могут быть отменены обработчиком. Автоматических повторов нет.
После аварийного завершения обработчика проверьте эффект процедуры перед повтором.

## Группы

Группы — общий справочник обеих подсистем. Откройте «Справочник групп» в меню:
создайте группу, переименуйте её или удалите. При удалении группы задания
сохраняются без группы. Существовавшие текстовые названия автоматически
переносятся в справочник при обновлении.

В настройках задания выберите группу из списка с поиском. На странице заданий
такой же поиск находится внутри фильтра групп. Выберите «Все группы», конкретную
группу или «Без группы» и нажмите кнопку фильтра.

Отметьте задания флажками или выберите все на текущей странице. Доступны действия:

- **Назначить группу** — объединить выбранные задания в существующую группу;
  «Без группы» снимает назначение.
- **Запустить повторно** — поставить новые запуски в очередь. Уже активные
  пропускаются. Процессы не прерываются.
- **В архив** — скрыть из основного списка и отключить расписания.
- **Вернуть из архива** — вернуть задания; расписания включаются отдельно.
- **Удалить** — убрать задания из списков и отключить расписания. Это логическое
  удаление: история запусков сохраняется. Таблицы источника и назначения не удаляются.

Все массовые действия требуют подтверждения списка. Архивирование и удаление
блокируются для всей выборки, если в ней есть активные операции. Ошибки в одном
задании отменяют массовое действие целиком. Группы организуют список и не задают
порядок выполнения. Для архива выберите «Архив» в фильтре списка.

Обновление через `windows/Update-Portal.ps1` применяет новые миграции и перезапускает
все включённые службы Windows (Web, SQL, ERP и Python, если установлен), даже если
до обновления они были остановлены. Явно отключённые службы остаются отключёнными.
При ошибке до изменения кода восстанавливается исходное состояние служб.
После обновления нажмите Ctrl+F5 в браузере.

### Отображение по группам

Список заданий обеих подсистем разбит на сворачиваемые разделы: название группы,
количество найденных заданий и карточки/строки внутри. Разделы первоначально
раскрыты; «Без группы» показывается последним. Поиск и фильтры применяются перед
группировкой. На странице размещаются до шести полных групп: задания одной группы
не разделяются между страницами. Массовое выделение действует на текущую страницу,
включая свёрнутые разделы.
