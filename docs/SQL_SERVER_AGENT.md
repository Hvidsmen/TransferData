# Существующие задания SQL Server Agent

Раздел **SQL Server Agent** в меню ETL Dev показывает задания исходного сервера,
а не копирует их в обработчики портала. На главной также есть ссылка «Задания vm-dwh».
Доступ к разделу имеют администраторы портала (`is_superuser`).

## Подключение

Используются активные подключения из справочника «1С Перенос данных → Подключения».
По умолчанию выбирается единственное подключение к `vm-dwh` с ролью назначения
или, если его нет, единственное другое подключение к этому серверу. При нескольких
кандидатах нужно выбрать подключение явно. Можно выбрать другой сервер из справочника.

Для чтения Agent временно открывается база **msdb** с существующими настройками
входа, драйвера и TLS. Сохранённая база DataWH не меняется. Для Windows-аутентификации
используется учётная запись процесса **веб-портала**; для SQL-аутентификации соответствующая
переменная секрета должна быть доступна веб-процессу, а не только worker.

Доступа только к DataWH недостаточно. DBA должен предоставить этому логину
доступ к msdb и чтение следующих метаданных:

- dbo.sysjobs, dbo.syscategories;
- dbo.sysjobhistory, dbo.sysjobactivity, dbo.syssessions;
- dbo.sysjobschedules, dbo.sysschedules, dbo.sysjobsteps.

SQLAgentReaderRole — стандартная роль просмотра всех заданий Agent, но возможность
выполнения именно этих прямых SELECT необходимо проверить в принятой модели прав.
Предоставлять sysadmin или права изменения заданий ради этого раздела не требуется.
Портал сам не создаёт пользователей и не выдаёт права.

## Сведения и обновление

Список показывает имя, категорию, включение задания, последний итог выполнения,
последний запуск и длительность (включая длительности больше 24 часов), все привязанные
расписания и следующее время по данным Agent. Есть поиск, фильтры и страницы по 30 строк.
Карточка показывает названия шагов, тип обработчика, базу шага, число повторов и
до 50 последних итогов задания (`step_id = 0`). Команды шагов, прокси, учётные данные
и тексты сообщений истории не запрашиваются.

Чтение выполняется непосредственно из msdb; снимки кэшируются на 15 секунд на
процесс веб-портала. В интерфейсе указан момент снимка. Сведения о расписаниях и
следующем запуске могут обновляться SQL Server Agent с собственной задержкой.
Даты выполнения отображаются в **локальном времени SQL Server**, момент снимка —
в часовом поясе портала. «Нет истории» не означает «никогда не запускалось»:
история могла быть очищена.

Незавершённая активность определяется по `sysjobactivity` в последней сессии
`syssessions`. Старые сессии не учитываются. При аварийной остановке самой службы
Agent её последняя сессия может остаться незавершённой: это не проверка здоровья
службы, поэтому интерфейс явно пишет «Есть незавершённая активность».

Раздел выполняет только SELECT. Запуск, остановка, удаление, изменение расписаний
и перенос заданий из SQL Server Agent не выполняются. Ошибка доступа или драйвера
показывается отдельно от пустого результата; тексты ошибок драйвера не выводятся,
поскольку они могут содержать секреты.
