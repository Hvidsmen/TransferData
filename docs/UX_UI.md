# Работа с обновлённым интерфейсом ETL Dev

Во всех трёх подсистемах используется одна структура карточек и табличного списка.
Переключатель «Карточки / Таблица» запоминается в браузере отдельно для подсистемы.
При переключении сохраняются выделенные задания; скрытые флажки не отправляются
в массовую операцию. Список остаётся доступным без JavaScript в виде карточек.

Главная показывает последние **операционные** результаты, а не случайную последнюю
проверку подключения. Успешный перенос не скрывается за последующей ошибкой проверки.
«Последний успех» сохраняется независимо от нового сбоя. Рядом показан следующий
запуск: SQL/Python используют сохранённое время планировщика; 1С рассчитывает время
с учётом своего ограничения одного планового запуска в день и уже занятого ключа
расписания. Это план, а не гарантия фактического старта.

«Требуют внимания» объединяет ошибки, прерванные операции, задержку расписания
более минуты (если нет активной операции) и очередь без свежего сигнала обработчика.
Отдельные фильтры показывают ошибки, работу/очередь и задания без запусков.
Это не проверка бизнес-SLA и не гарантия актуальности содержимого внешней таблицы.

## Сигналы обработчиков

SQL обновляет `sql-worker.heartbeat` каждые 5 секунд, в том числе во время долгой
загрузки. При корректной остановке файл удаляется. Python использует существующий
`python-worker.heartbeat`, 1С — `WorkerLease` в служебной базе.
Сигнал старше 60 секунд, некорректная/неизвестная дата или дата более чем на 5 секунд
в будущем не показываются зелёным. Состояние «Нет свежего сигнала» предлагает
проверить соответствующую задачу Windows и не утверждает, что процесса точно нет.
Во время обновления портала отображается отдельное состояние паузы.

Автообновление сохраняет текущую форму и её значения. При пропадании связи
показывается предупреждение; просмотренные данные могут быть устаревшими.

## Настройка задания

Форма последовательно показывает источник, данные, назначение, расписание и
сводку перед сохранением. Для Python и процедуры ненужный шаг назначения
пропускается. Технические параметры вынесены в раскрываемый блок.
Сервер остаётся источником окончательной проверки, ошибки открывают нужный шаг.
Шаг «Проверка» — просмотр настроек, а не тест соединения с внешними базами.
Без JavaScript доступна полная обычная форма.

## Ход операции и ошибки

Ожидание обработчика отличается от выполнения. Показываются время ожидания,
этап и, когда доступны, обработанные строки. SQL до коммита явно указывает,
что записи ещё находятся в транзакции. Общий объём не оценивается вымышленным
процентом. Для Python известные `total`/`completed` дают реальный прогресс.

Ошибки содержат краткую подсказку, раскрываемое исходное безопасное сообщение
и кнопку копирования. Неизвестная причина не подменяется предполагаемой.
Строки драйвера и значения строк базы ради интерфейса дополнительно не сохраняются.
Удаление остаётся доступным через меню действий, с обязательной серверной страницей
подтверждения; история и внешние таблицы сохраняются.
