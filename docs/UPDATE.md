# Одна команда обновления ETL Dev

После настройки трёх задач Task Scheduler запустите из каталога проекта:

```powershell
.\windows\Update-Portal.ps1
```

Скрипт управляет **задачами Планировщика, не службами Windows**. Имена по умолчанию:
`ETL Dev — Web`, `ETL Dev — TransferData`, `ETL Dev — ERP` (длинное тире).
Все три должны запускать `windows/Start-Panel.ps1` из этого проекта с разными
режимами web / worker / erp-worker, под одним пользователем. Сам updater запускайте
под тем же пользователем, с правами управления его задачами. Это также важно
для установки pip --user и доступа к DPAPI. Скрипт не запрашивает пароли и не
читает их значения.

## Первое подключение updater

Нужна версия worker с поддержкой паузы. Поэтому **один раз** обновите пакет вручную
и перезапустите старые web/worker после завершения активных загрузок:

```powershell
git pull origin main
py -m pip install --user --no-build-isolation .
```

После этого используйте только `Update-Portal.ps1` для обычных обновлений.
Если старый worker не подтвердил паузу за 10 минут, updater не будет его убивать:
он отменит обновление, вернёт доступ web и сообщит о необходимости перезапуска.

## Что делает команда

1. Проверяет пользователя, имена/режимы задач, ветку main и возможность fast-forward.
   Fetch выполняется до остановки. Локальные изменения, пересекающиеся с incoming
   файлами, вызывают отказ без reset/stash. Остальные локальные файлы сохраняются.
2. Выставляет maintenance.flag, отключает три задачи от автоматического старта
   и останавливает web. Каждый worker заканчивает текущую загрузку и подтверждает
   паузу между заданиями. Новые действия через API и CLI на время паузы запрещены.
3. Только после подтверждения останавливает worker и ждёт завершения процессов.
4. Создаёт закрытую NTFS-копию в `.backups/<дата-id>`: `.state`, config.json,
   архив исходного коммита, локальные файлы и исходные состояния задач.
   Временные файлы паузы из резервной копии исключаются.
5. Выполняет fast-forward, установку зависимостей, migrate, collectstatic, check.
   Для текущей пользовательской установки используется pip --user; для рабочей
   `.venv` — py -m uv sync --locked, как при установке через uv.
6. Восстанавливает Enabled и Running для задач. Остановленные до обновления
   задачи сами не запускаются. После старта снимает паузу.

Скрипт не прерывает загрузку по тайм-ауту. Можно увеличить ожидание:

```powershell
.\windows\Update-Portal.ps1 -WaitSeconds 1800
```

Свои имена/папку задач можно передать явно:

```powershell
.\windows\Update-Portal.ps1 -TaskName 'My Web','My TransferData','My ERP' -TaskPath '\ETL\'
```

Если нет трёх задач, другой Windows-пользователь или нет прав на их изменение,
команда остановится с ошибкой. Она не создаёт задачи и не меняет их Windows-пароли.

## Ошибка обновления

До изменения кода/зависимостей — пауза снимается, исходные состояния задач
восстанавливаются. После начала изменения кода/зависимостей — задачи остаются
остановленными и отключёнными, пауза сохраняется. Скрипт выводит путь к резервной
копии и причину. Автоматического отката миграций/пакетов нет: он мог бы повредить
данные после изменения схемы. Сначала устраните ошибку, повторите необходимые
install/migrate/collectstatic/check вручную, затем удалите maintenance.flag
и восстановите задачи по task-states.json в резервной копии.

Не удаляйте паузу и не включайте задачи до проверки согласованности версии кода,
зависимостей и схемы БД. Не восстанавливайте SQLite поверх работающих процессов.
Резервные копии содержат ключ Django и зашифрованные DPAPI-файлы, поэтому
ограничены текущим пользователем, SYSTEM и администраторами, и исключены из Git.

Пауза и отказы постановки заданий проверены тестами; PowerShell-синтаксис проверен
парсером. Операции Task Scheduler/NTFS в текущей Linux-среде не выполнялись — первый
полный запуск нужно проверить на vm-dwh.
