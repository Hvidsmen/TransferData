# Сотрудники с дополнительными реквизитами

Подготовка читает структуру `Справочник.Сотрудники`, табличную часть
`ДополнительныеРеквизиты` и объект, на который ссылается её поле `Свойство`.
Названия колонок берутся из `Наименование` этого объекта, а не угадываются
по физическим именам `_Fld…`. Включаются все свойства, имеющие строки в табличной
части сотрудников (в том числе с пустым значением). Свойства, которые лишь
существуют в общем каталоге свойств, но ни разу не записаны сотрудникам,
не включаются: каталог может содержать свойства других объектов.

После обновления портала выполните в PowerShell на сервере:

```powershell
cd "C:\Users\ETLadmin\Desktop\TransferData"
py -m transferdata.web prepare_employee_attributes --connection "ERP — источник" --target-connection "DWH — назначение" --create-job
```

Если портал установлен в `.venv`, вместо `py` используйте
`& .\.venv\Scripts\python.exe`. Названия подключений должны совпадать с порталом.
Для другого имени объекта используйте `--object "Справочник.СотрудникиОрганизаций"`
(только если такой объект действительно есть в конфигурации).

Команда создаёт новое задание `Сотрудники · все дополнительные реквизиты`
в разделе «1С Перенос данных», назначение `erp_ai.EmployeesExpanded`.
SELECT сохраняется в `.state/EmployeesExpanded.sql`. Существующие файлы и задания
не перезаписываются. Источник используется только для SELECT, создание таблицы
и загрузка назначения выполняются отдельно при запуске задания в портале.
Расписание нового задания выключено. Перед включением проверьте ручной запуск.

Одна строка соответствует одному сотруднику; сотрудники без дополнительных
свойств остаются в выгрузке с NULL. Например, `Email` содержит читаемое значение.
Для составного типа сохраняются также `Email__String`, `Email__Tag` и остальные
физические компоненты значения. Ссылки получают представление и отдельную колонку
с идентификатором; документы — также дату и номер. Пустое/неподдержанное
представление не уничтожает исходную ссылку. Даты корректируются по правилу
YEAR < 3753, иначе минус 2000 лет.

Повтор одного свойства у одного сотрудника вызывает ошибку SQL вместо выбора
случайного значения. Разделители данных учитываются в связях. Если одно свойство
имеет разные названия в разных областях данных, подготовка останавливается.
Совпадающие, длинные и небезопасные имена колонок получают безопасные уникальные
алиасы. Выгрузка ограничена 1000 колонками. На большом числе свойств запрос может
быть тяжёлым: сначала проверьте время выполнения на копии/реплике 1С.

Состав колонок фиксируется при подготовке: новые значения уже известных свойств
загружаются автоматически; новые свойства требуют повторной подготовки SELECT
с другим `--output` и проверки схемы назначения. Изменение существующего задания
или расширение таблицы автоматически не выполняется.

## Физические лица

Та же подготовка доступна отдельной командой:

```powershell
cd "C:\Users\ETLadmin\Desktop\TransferData"
py -m transferdata.web prepare_individual_attributes --connection "ERP — источник" --target-connection "DWH — назначение" --create-job
```

Создаётся отдельное задание `Физические лица · все дополнительные реквизиты`,
таблица назначения `erp_ai.IndividualsExpanded`, SQL-файл
`.state/IndividualsExpanded.sql`. Сотрудники не изменяются. Источник —
`Справочник.ФизическиеЛица`; если в конфигурации другое имя, задайте `--object`.
Расписание выключено до ручной проверки. Требуется табличная часть
`ДополнительныеРеквизиты`; контакты из других регистров в эту выгрузку
автоматически не включаются.
