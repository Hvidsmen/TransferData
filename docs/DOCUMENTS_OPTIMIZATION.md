На vm-dwh исследуется `ERP to DWH Документы`, шаг 41. Изменения рабочего job,
его расписания, процедур и таблиц этим пакетом **не выполняются**.

Шаг 5 дополнительно извлекает данные из ERP и удаляет дубликаты через ROW_NUMBER
с порядком только по ссылке. При оптимизации нельзя произвольно менять выбор
сохраняемой строки. На этом этапе исследуем только шаг 41.

Поэтому отсутствие их в выборке sys.tables не означает отсутствия источника.

## Выполнение

Обновить репозиторий на сервере:

```powershell
cd "C:\Users\ETLadmin\Desktop\TransferData"
git pull --ff-only origin main
```

В SSMS на **vm-dwh** открыть и выполнить целиком
`tools/sql/Measure-CommercialOffers.sql`. Это **реальный замер**, а не только
установка: он читает оба источника, записывает полные пробные копии в DataWH
и строит пять индексов. Не нужен перезапуск портала или SQL Server.

Запускать вне тяжёлых загрузок, при готовых исходных данных. Ориентир дополнительного
места — размер двух копий с индексами (ранее около 5,4 GiB), **плюс** запас для
изменившегося объёма, журнала и tempdb при сортировках. Это не расчёт пикового
потребления. Каждый новый запуск оставляет ещё одну пару таблиц.

Скрипт:

1. Проверяет машину, отсутствие внешней транзакции, источник и собственный marker.
2. Создаёт схему `document_trial`, журнал MeasureRuns/MeasurePhases, если их нет.
3. Показывает тип исходных объектов, RunId и SessionId.
4. Копирует шапки и товары в `OfferHeaders_<GUID>` и `OfferLines_<GUID>`.
   Фактическое количество строк фиксируется сразу после копирования без COUNT-скана.
5. По одному строит три индекса шапок (Ссылка, DocumentKey, Номер) и два индекса
   строк (Ссылка, НомерСтроки), как в оригинальном шаге. Индексы не уникальные,
   состав, последовательность и SELECT * сохранены.
6. Возвращает семь длительностей, общий итог, имена пробных таблиц и их размеры.

Он не вызывает transferTalbeToDatWHErp, потому что та процедура пересоздаёт
действующие erp-таблицы. Не вызывает процедуры извлечения из ERP и не меняет исходные
данные. Если источник — view, выполняется его определение, включая удалённые чтения,
если они в нём есть; их стоимость тоже входит во время копирования.
Session applock исключает параллельные запуски нашего замера; другие ETL он не
блокирует автоматически. Отдельные операции выполняются с обычными настройками
SQL Server, без NOLOCK, принудительного MAXDOP, очистки кэшей и смены recovery model.
Поэтому время в SSMS не обязано точно повторять время Agent: нагрузка, кэш,
настройки сессии и рост файлов могут отличаться. OptionsFlags сохраняет @@OPTIONS.

## Прогресс и результаты

Во вкладке «Сообщения» сразу появляется название текущего этапа. В другом окне:

```sql
USE [DataWH];
SELECT TOP (5) * FROM document_trial.MeasureRuns ORDER BY StartedAtUTC DESC;
SELECT * FROM document_trial.MeasurePhases
WHERE RunId = 'ВСТАВЬТЕ-ВАШ-RUNID'
ORDER BY Ordinal;
```

Время журнала — UTC, длительности — минуты. Если запрос оборван или сессия
аварийно закрыта, запись running может остаться без финального статуса: она сама
по себе не доказывает, что запрос ещё работает. Не запускать второй замер для
«оживления» первого. Ошибка обычного выполнения фиксируется с её SQL-номером,
а завершённые этапы и пробные таблицы сохраняются для разбора.

После выполнения прислать таблицы Phase/RowsCopied/Minutes и размеры. По ним
выберем, что оптимизировать: чтение источника, запись копии или построение
конкретного индекса. До этого нет основания удалять индексы или переносить
обработку на инкрементальную схему.

Автоматического удаления результатов нет. Для очистки после разбора использовать
точные имена из MeasureRuns, только собственные GUID-таблицы в document_trial,
при отсутствии активного замера. Не удалять всю схему или журнал. Освобождение
места внутри файлов не требует SHRINK. Если замер прерван на SELECT INTO, может
остаться пустая пробная таблица; её также сначала идентифицируют по RunId/имени.

При подготовке проверяется синтаксис, но реальное выполнение SQL Server нужно
проверить на vm-dwh. Этот замер ещё не является оптимизированной загрузкой или
публикацией. Переключение цен и данные price_trial он не затрагивает.
