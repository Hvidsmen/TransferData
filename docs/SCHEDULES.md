# Удобное расписание ETL Dev

Откройте задание → «Настроить» → «Расписание».

- **Ежедневно**: выберите время начала, например 09:30.
- **Еженедельно**: отметьте один или несколько дней недели и выберите время.
- **Ежемесячно**: выберите число 1–31 и время. Если такого числа нет в месяце,
  запуск в этом месяце пропускается (например, 31 апреля не существует).

Включите расписание соответствующим переключателем и сохраните задание.
Время выбирается в 24-часовом формате. В TransferData применяется часовой пояс
из поля задания, в ERP_to_DWH — часовой пояс портала (по умолчанию Europe/Moscow).
Под селекторами показывается понятное описание будущего расписания.
Карточки и списки заданий тоже показывают его обычным текстом.

Расписания работают, пока запущен worker соответствующей подсистемы. Не нужно
создавать отдельную Windows-задачу для каждого переноса: постоянные worker
занимаются расписаниями внутри портала.

## Существующие задания

TransferData продолжает хранить cron; селекторы преобразуют его автоматически.
Старые простые расписания раскрываются в селекторах без изменения времени.
Сложные cron сохраняются и открываются в режиме «Расширенное расписание».
В этом режиме нужно пять полей, например `0 2 * * *` для ежедневного запуска
в 02:00. Четыре поля (`10 * * *`) не являются корректным cron этого сервиса.

ERP_to_DWH получает новое поле schedule_cron через миграцию. До редактирования
старые задания продолжают работать по прежнему ежедневному schedule_time.
После сохранения селекторы задают день/дни и время. Расширенный произвольный cron
для ERP не предлагается: её уникальный schedule_key по-прежнему допускает только
один плановый запуск задания за день. Изменение времени не повторяет уже созданный
плановый запуск этого дня. Ручной запуск остаётся отдельным действием.

После изменения cron TransferData пересчитывает следующий запуск, как прежде.
Поведение пропущенных запусков и защиту от параллельного исполнения не меняли.

## Обновление

Используйте `windows/Update-Portal.ps1`, если он уже подключён. Скрипт ожидает
завершения текущих переносов, выполняет миграцию, сборку статики и перезапускает
задачи. Если обновляете вручную: после завершения загрузок остановите web/worker,
обновите код и пакет, выполните migrate и collectstatic, затем запустите процессы.
Не забудьте обновить страницу браузера Ctrl+F5.
