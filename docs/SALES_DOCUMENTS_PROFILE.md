# Профиль исходного извлечения реализаций

Ни удаление 43 индексов, ни сужение 33 справочников не дали устойчивого выигрыша
общего времени в обоих порядках запуска. Рабочую процедуру пока не изменяли.
Следующий шаг — разложить исходное время и посмотреть фактический план 45 JOIN.

## Запуск на vm-dwh

Получить main. В SSMS открыть **tools/sql/Profile-SalesDocuments.sql** в новом
окне без транзакции и выполнить целиком вне основной загрузки, на готовой ERP-копии.
Пункт SSMS «Включить фактический план выполнения» (Ctrl+M) должен быть выключен:
скрипт сам включает STATISTICS XML только для финального SELECT. Системные кеши
не очищать. Нужны прежние права чтения/создания пробных таблиц и SHOWPLAN в
1CUnloading, DataWH, tempdb; они проверяются до извлечения, права не выдаются.

Это **один проход исходного варианта**: все 77 индексов и SELECT * остаются.
Исходная процедура читается через OBJECT_DEFINITION и не вызывается/заменяется.
DROP/SELECT INTO её результата перенаправлены в уникальную
DataWH.document_trial.SalesProfile_<GUID>. Сохраняется живой исходный SQL,
комментарии, фильтры, UNION ALL, COALESCE, поля и все 45 LEFT JOIN. Прежние guard
ожидают заголовок, 77/43 индекса, цели записей, 35 temp-чтений и 45 JOIN; при отказе
не править числа без разбора изменившегося текста. Никаких изменений Agent,
рабочих таблиц, переноса товаров и дедупликации. Сравнения данных и MATCH здесь
нет: диагностируется неизменённая исходная логика, а не новая оптимизация.

Создаётся одна постоянная копия шапок (ранее около 2,5 GiB) и temp-таблицы
внутри динамического batch. Нужен запас tempdb/журналов. Копия остаётся для анализа.
Время каждого чтения включает SELECT INTO и запись tempdb, а не только сетевое чтение.
Локальное ожидание блокировки ограничено 30 секундами; это не общий timeout,
не предел удалённых ожиданий и не ограничение времени вычисления/отката.

## Какие времена получаем

SalesProfileRuns: RunId, SessionId, SourceHash текста, итог, TotalMinutes,
имя приватного результата. SalesProfilePhases содержит:

- read_orders — составной источник заказов и заявок на возврат;
- read_fact — полное чтение основного набора реализаций;
- read_lookup — 33 отдельных чтения справочников/связанных документов;
- final_join — финальный SELECT с 45 JOIN и записью готовых шапок в приватную таблицу.

SalesProfileIndexes хранит все 77 времён индексов. Они не включены повторно во
время чтения. Суммы фаз/индексов могут быть меньше TotalMinutes: компиляция,
логирование, освобождение temp-таблиц и отправка плана также требуют времени.
Число строк фиксируется сразу после SELECT INTO, до команд настройки плана.
Фазы пишутся вне общей транзакции; BEGIN/COMMIT между EXEC не переносятся.

Скрипт финального SELECT вызывается во вложенном sp_executesql. Он видит temp-
таблицы родительского batch, читает те же данные и возвращает фактический XML-план.
Temp-наборы для финального соединения не копируются заново. Новый контекст
компиляции и инструментализация имеют стоимость: это диагностический профиль,
а не доказательство тождественного времени рабочего шага или ускорения.
Final_join включает соединения **и запись результата**, а также накладные расходы
сбора/передачи плана; это не отдельная оценка стоимости только JOIN в памяти.
Время CPU/elapsed, строки, memory grant и spills уточняем по фактическому плану.

## Что прислать

После выполнения ожидается Status=success. Пришлите итоговые таблицы:
TotalMinutes, суммы read_fact/read_orders/read_lookup/final_join и IndexMinutes.
Затем отдельный XML-план: среди результатов будет ссылка с ShowPlanXML. Открыть
её и сохранить XML файлом с расширением **.sqlplan**, затем приложить файл.
Если XML-строк несколько, нужен план SELECT INTO SalesProfile_<GUID> с 45 JOIN.
Не заменять его скриншотом общего дерева: для анализа нужны свойства операторов.
Если SSMS обрезает XML, увеличить лимит XML в настройках результатов до Unlimited.
План не записывается автоматически на серверный диск и не берётся из кеша
оценочных планов. SET STATISTICS XML сбрасывается после финального SELECT и в CATCH.

Если этап не меняется несколько минут, выполнить Check-SalesDocuments.sql в
**другом** окне: он выбирает последний запуск среди index/narrow/profile и выводит
текущий statement/wait, фазы и memory grant. Не отменять вслепую и не ждать часами.
Статус running после отмены не доказывает активность; session-lock может остаться
до закрытия исходной сессии. Сам диагностический файл ничего не завершает.

Подготовка проверяется T-SQL-парсером и локальными проверками репозитория.
Облачная среда не подключена к реальному SQL Server; результат/фактический план
получаем выполнением на vm-dwh.
