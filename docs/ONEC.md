# Метаданные 1С из SQL-базы ERP

ERP_to_DWH читает каталог объектов и физическую структуру непосредственно из
служебных таблиц базы 1С. Номера `_Reference…` и `_Fld…` не угадываются.
Установка платформы 1С, COM-соединение и выгрузка конфигурации не требуются.

Используется MIT-библиотека **DaJet.Metadata 5.1.5**, исходный репозиторий:
https://github.com/zhichkin/dajet-metadata, коммит
`3058bb4c5b92e70afa299d9f106f2ef9cfeded07`. Это отдельный MIT-проект,
а не поставка полной платформы DaJet. Версии NuGet и контрольные суммы зависимостей
зафиксированы в `tools/OneCMetadata/packages.lock.json`. Уведомление о лицензии
копируется в сборку помощника.

## Однократная установка на vm-dwh

Под `DAICHI\ETLadmin` в каталоге TransferData обновите портал и установите помощник:

```powershell
.\windows\Update-Portal.ps1
.\windows\Install-1CMetadata.ps1
```

Установщик использует SDK .NET 10, если он уже доступен, иначе скачивает официальный
SDK **10.0.402 win-x64** с `builds.dotnet.microsoft.com`. Архив проверяется по SHA512
из официального release manifest. NuGet восстанавливается в locked mode.
Корпоративный прокси должен разрешать Microsoft downloads и NuGet (`api.nuget.org`,
`globalcdn.nuget.org`). Отключать проверку TLS скачивания не требуется.

SDK, пакеты, помощник и его библиотечные диагностические файлы находятся в
`.tools/onec/` с закрытым NTFS ACL сервисной учётной записи. Системная установка
.NET и изменение PATH не нужны. `.state/onec-helper.json` содержит только пути
к dotnet и DLL, без паролей. Не удаляйте `.tools/onec` после установки.
При последующих обновлениях Update-Portal пересобирает установленного помощника
перед возобновлением обработчиков. Старые каталоги сборок сохраняются.

Установщик проверен синтаксически для PowerShell; сборка и протокол помощника
проверены на .NET в Linux. Установка на Windows и чтение конкретной базы 1С
требуют проверки на вашем сервере. Реальный 1С SQL Server в тестовой среде недоступен.

## Работа в портале

1. Откройте **Метаданные 1С** в меню. Выберите подключение источника ERP_to_DWH.
2. Нажмите **Прочитать каталог из базы 1С**. Операция выполняется ERP-worker,
   её состояние обновляется автоматически. Веб-страница не ждёт SQL-ответа.
3. Найдите, например, **БизнесРегионы** и откройте `Справочник.БизнесРегионы`.
4. Нажмите **Получить структуру из базы**. Будут показаны физическая таблица,
   реквизиты и имена столбцов для DWH.
5. Нажмите **Создать перенос этого объекта**, выберите назначение и целевую таблицу.
   Тип источника будет **Объект 1С**, подключение и объект подставятся автоматически.
6. Выполните ручной запуск, проверьте данные, затем включите расписание.

Используется существующее Windows-задание **ETL Dev — ERP**. Новая служба не нужна.
Windows Authentication выполняется под пользователем ERP-worker; SQL Authentication
берёт пароль из его окружения по `credential_reference`. Пароль передаётся помощнику
через stdin, не через аргументы командной строки, и не сохраняется в метаданных.
Настройки Encrypt=yes и trust_server_certificate берутся из ERP-подключения.
Сервисному пользователю требуется SELECT на служебные таблицы конфигурации 1С
(включая используемые версией Config, Params, DBNames/SchemaStorage и расширения).
Помощник не выполняет DDL и не изменяет базу источника.

Чтение метаданных обслуживается тем же последовательным ERP-worker, когда нет
задания загрузки. Одновременно допускается одно чтение на подключение. Максимум
времени помощника — 10 минут. При ошибке/прерывании предыдущий каталог и структуры
сохраняются. После остановки worker незавершённое чтение нужно запустить повторно.

## Что восстанавливается, а что остаётся в формате 1С

- Каталог имён объектов и физическая таблица основного объекта берутся из метаданных.
- Реквизит с одним физическим полем становится столбцом с его именем 1С.
- Составные типы сохраняются отдельными столбцами, например `Регион__Tag`,
  `Регион__TypeCode`, `Регион__Identity`: компоненты не теряются.
- Длинные/совпадающие имена SQL aliases сокращаются/различаются детерминированно.
- Двоичные ссылки не превращаются в наименования или UUID автоматически.
- Системная `ВерсияДанных` читается явным CONVERT в binary(8), сохраняя байты:
  SQL Server rowversion нельзя копировать в целевую колонку rowversion явным INSERT.
- В задании «Объект 1С» по умолчанию включено «Корректировать даты 1С»:
  `CASE WHEN YEAR(поле) < 3753 THEN поле ELSE DATEADD(year, -2000, поле) END`.
  Обычные даты остаются как есть; 4026 год превращается в 2026. Дата с годом 3753
  становится 1753, год 3752 не меняется; NULL остаётся NULL. Правило применяется
  только к столбцам, определённым метаданными как дата, включая компоненты
  составных типов. Флажок можно отключить для сохранения исходных дат.
  Для обычного TABLE/SQL_QUERY это правило автоматически не применяется.
  Сгенерированный SELECT можно раскрыть на странице задания.
- Булевы, иерархия и другие значения сохраняют семантику физического SQL-хранилища.
- Табличные части показаны отдельно; автоматический перенос выбранного объекта
  загружает только основную таблицу. Табличную часть можно загрузить отдельным
  заданием по её физической таблице.
- Виртуальные таблицы и язык запросов 1С этим источником не исполняются.

Это восстановление структуры, а не полная реализация языка/представлений платформы 1С.
Совместимость расширений и версий платформы определяется используемым парсером.
Неподдерживаемые структуры приводят к ошибке, а не к угадыванию таблицы.

## Изменение конфигурации 1С

Каталог обновляется вручную кнопкой чтения. Старые объекты, исчезнувшие из каталога,
помечаются неактивными. При смене сервера/базы/параметров доступа старые структуры
не используются: сначала перечитайте каталог и нужный объект.

Задание хранит снимок соответствия столбцов. Если перечитанная структура изменилась,
старое задание блокируется до повторного сохранения настроек. Автоматического
изменения существующей целевой таблицы DWH нет: несовместимая схема блокирует
публикацию по обычным правилам ERP_to_DWH. После обновления 1С перечитайте структуру
нужных объектов и проверьте целевые таблицы перед возобновлением расписаний.

## Индикатор чтения и ожидание обработчика

Карточка операции показывает реальные этапы: заявка принята, ожидание обработчика,
чтение базы, сохранение. Полоса во время работы показывает активность без выдуманного
процента: библиотека 1С не сообщает процент чтения. Таймер отдельно считает ожидание
и чтение; после завершения показывает общее время. Статус обновляется автоматически.
Если в очереди нет свежего сигнала ERP-worker, портал предлагает проверить задачу
«ETL Dev — ERP». В планировщике `Ready` означает, что задача сейчас не выполняется;
для постоянной обработки ожидается `Running`. При длительном чтении worker продолжает
посылать сигнал активности.
