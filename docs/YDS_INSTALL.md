# etl-dev-yds: отдельная установка для новой компании

Адрес: **http://192.168.70.9:8003/**. Подсистемы: **1С Перенос данных**
(SQL Server → SQL Server) и **Python обработчик**. SQL-переносы в PostgreSQL
и SQL Server Agent отключены в меню, обзоре и HTTP-маршрутах. Привязанный к
DataWH обработчик коммерческих предложений недоступен; Python-задания используют
собственные `.py` файлы. Общий код и ветка `main` остаются едиными.

Это независимое развёртывание, не многопользовательский режим в базе первой
компании. Нельзя переносить `.state`, `.backups`, `config.json`, пароли, файлы
учётных данных и персональные выгрузки с другого сервера. Нужен чистый checkout.
Существующая установка без файла профиля продолжает работать в полном режиме.

## Установка на Windows-сервере 192.168.70.9

Подготовьте Windows x64, Git, Python 3.12+ x64 с доступной командой `py` или `python` и ODBC Driver
17/18 for SQL Server. Выберите Windows-учётную запись будущих служб: ей нужны
права на каталог, пакетный вход и необходимые базы. Установку выполняйте от неё,
запустив PowerShell с повышенными правами. Имена баз и учётные данные первой
компании нигде не подставляются.

```powershell
python -m pip install --user uv

git clone --branch main --single-branch https://github.com/Hvidsmen/TransferData.git C:\etl-dev-yds
cd C:\etl-dev-yds
.\windows\Install-YDS.ps1 -OpenFirewall
```

Для приватного репозитория потребуется доступ GitHub под этой Windows-учётной
записью. Вход выполняется стандартными средствами Git; токены в скрипты не
записывайте. Порт 8003 до установки должен быть свободен. Параметр `-OpenFirewall`
открывает TCP/8003 только для LocalSubnet в профилях Domain/Private. Если клиенты
приходят из другой подсети, согласуйте отдельное правило с администратором сети.
Если правило уже настроено извне, параметр можно опустить.

Установщик:

1. Создаёт `.state/deployment.json` с `{"version":1,"profile":"yds"}` и ограничивает
   доступ к `.state` учётной записью установки, SYSTEM и администраторами.
2. Устанавливает зависимости в отдельную `.venv`, создаёт новую SQLite-базу
   служебных данных, ключ Django и статические файлы.
3. Собирает помощник метаданных 1С (при необходимости скачивает официальный .NET
   SDK). Этот шаг может занять несколько минут и требует исходящего HTTPS.
4. Запрашивает нового администратора портала (при повторе собственной установки
   уже созданный администратор сохраняется).
5. Один раз запрашивает Windows-пароль для регистрации задач планировщика:
   `etl-dev-yds — Web`, `etl-dev-yds — ERP`, `etl-dev-yds — Python`,
   `etl-dev-yds — Update`. Пароль хранит планировщик Windows, не портал.
6. Запускает службы, ожидает новые сигналы ERP/Python и проверяет страницу входа.

Для постоянных обработчиков сразу заданы отсутствие лимита времени,
автоперезапуск при ошибке через минуту и запрет параллельных экземпляров.
Задача Update запускается только по требованию. Существующие задачи не
перезаписываются. При сбое регистрации/запуска удаляются только задачи,
созданные текущей попыткой; локальная база и журнал остаются для диагностики.
На реальном Windows-сервере цикл установки нужно подтвердить: облачные проверки
не воспроизводят Windows-аутентификацию и доступ к SQL Server.

## Первые настройки

Откройте **http://192.168.70.9:8003/**, войдите новым администратором.
В разделе **1С Перенос данных → Подключения** создайте:

- источник с реальным сервером и базой 1С новой компании;
- назначение с её сервером SQL Server и базой DWH.

Выберите установленный ODBC-драйвер, задайте тип аутентификации и TLS.
При SQL-аутентификации пароль задаётся переменной окружения именно учётной
записи ERP-обработчика. Проверка из Web и выполнение ERP должны иметь необходимые
права на соответствующие базы. Источник рекомендуется подключать с правами
SELECT, по возможности к копии/реплике.

Затем прочитайте каталог в **Метаданные 1С**, получите структуру нужного объекта,
создайте задание и проверьте ручную загрузку до включения расписания.
Для Python положите скрипты в `C:\etl-dev-yds\.state\python-scripts` и создайте
задания с относительными путями. Зависимости собственных скриптов должны быть
описаны и установлены в `.venv`; временная ручная установка пакетов может быть
удалена последующим `uv sync --locked`, поэтому согласуйте их в `pyproject.toml`
и `uv.lock` до автоматических обновлений.

Команды диагностики из каталога установки:

```powershell
cd C:\etl-dev-yds
& .\.venv\Scripts\python.exe -m transferdata.web erp_worker_status
Get-ScheduledTask | Where-Object { $_.TaskName -like 'etl-dev-yds*' } | Select-Object TaskName, State
```

## Последующие обновления

В административном разделе **Обновление портала** нажмите кнопку обновления.
Обслуживаются только задачи этого профиля: Web, ERP и Python. Задача SQL не нужна.
Профиль находится в локальной `.state` и сохраняется при обновлении. Резервные
копии содержат секреты и служебные данные этой компании и остаются на её сервере.
Перед автоматическим обновлением убедитесь, что `git fetch origin` работает без
запроса пароля под той же Windows-учётной записью.

Ручной вариант:

```powershell
cd C:\etl-dev-yds
git pull --ff-only origin main
.\windows\Update-Portal.ps1
```
