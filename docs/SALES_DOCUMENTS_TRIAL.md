# Шаг 5: реализация товаров и услуг

Аудит предоставленного sp_Документы.РеализацияТоваровУслуг:
77 некластерных индексов временных таблиц, из них 43 на большой таблице
#РеализацияТоваровУслуг; 45 LEFT JOIN. Многие справочники читаются SELECT *.
Извлечение реализовано полным чтением; фильтр даты в предоставленном коде
закомментирован. Процедура создаёт шапки, но не загружает таблицу товаров:
её происхождение проверяем отдельно, не считаем свежей автоматически.

Первый кандидат меняет только создание 43 индексов большой временной таблицы.
Индексы справочников, все поля, LEFT JOIN, UNION ALL источников заказов/возвратов,
COALESCE и текущая кратность соединений сохраняются. Это гипотеза: удаление
индексов может ухудшить план. Прирост скорости до замера не заявляется.

## Пробный запуск

На vm-dwh получить main и вне ETL, на готовой стабильной ERP-копии, выполнить
целиком **tools/sql/Compare-SalesDocumentsIndexes.sql** в новом окне SSMS.
Требуются VIEW DEFINITION исходной процедуры и прежние права чтения ERP,
создания таблиц в DataWH.document_trial. SQL Server в облаке недоступен.

Скрипт читает оригинальное определение непосредственно из sys.sql_modules:
плоский текст из чата не исполняется, исходные комментарии и строки сохраняются.
Отказывается при неожиданном заголовке, числе индексов (77/43), трёх ссылках
на целевую таблицу, дополнительных CREATE/записях/вызовах, блочных комментариях
и посторонних постоянных целях. Не обходить отказ редактированием чисел наугад.

Оба варианта исполняются в контексте 1CUnloading, но выходной DROP/SELECT INTO
перенаправлен в уникальную **DataWH.document_trial.SalesBase_<GUID>** либо
**SalesNoFactIndex_<GUID>**. Временные таблицы живут только внутри своего
sp_executesql и освобождаются при возврате. Транзакция через EXEC не переносится.
Исходная процедура не запускается и не заменяется; Agent, рабочие таблицы,
товары, цена и коммерческие предложения не изменяются. Снимки результатов
сохраняются для разбора; каждый новый запуск создаёт ещё две полные копии шапок.
Нужен запас места для них, tempdb и журналов; системные кеши не очищаются.

Первым обычно baseline; @CandidateFirst=1 меняет порядок для повторного замера,
если первый показывает пользу. Сравниваем полные BaselineMinutes/CandidateMinutes:
они включают удалённые чтения, tempdb, индексы, join и запись результата в DataWH.
Это **извлечение шапок**, не весь шаг 5: второе копирование шапок, перенос товаров,
рабочее удаление дубликатов и индекс Ссылка здесь не измеряются.

Индексы инструментированы одинаково: время каждого записывается в
DataWH.document_trial.SalesExtractIndexes. В конце показывается суммарное время
индексов и отдельно индексов большой таблицы. Добавлен небольшой одинаковый
расход логирования оставшихся индексов; результаты также зависят от общего кеша
и нагрузки на ERP/SQL Server. Новых индексов на ERP нет.

Полная сверка структуры и всех значений с количеством копий одинаковых строк
выполняется отдельно от времени извлечения. Текст и бинарные данные сравниваются
побайтно с длиной. Значения не проверяются только по хешам. SourceHash относится
к тексту процедуры для идентификации версии, не к сравнению строк.
Все исходные дубликаты сохраняются: рабочий ROW_NUMBER(PARTITION BY Ссылка ORDER BY
Ссылка) выбирает произвольную строку, поэтому сравнение проводится **до** такого
удаления. Разные планы могут менять произвольного победителя при неодинаковых
дубликатах. Перед рабочим переключением отдельно проверяем такие группы:
этот опыт не доказывает эквивалентность произвольного выбора строки.

Ожидается Status=MATCH. При различиях, смене схемы или изменении источника между
двумя чтениями скрипт завершается ошибкой и сохраняет копии. Полная сверка может
занимать десятки минут дополнительно к двум извлечениям. Рабочий шаг не переключается.
Локальное ожидание блокировки ограничено 30 секундами; это не общий timeout SQL
и не предел удалённого ожидания. При отмене проверить состояние сессии и закрыть
её после завершения отката: session-lock может сохраниться.

Пришлите итоговые две таблицы (время обоих вариантов и индексов) и MATCH либо ошибку.
Отдельно выполнить Check-SalesDocuments.sql: размеры, типы объектов и история
шага помогают выбрать следующий участок; он не запускает процедуру.
