# Python обработчик

Третья подсистема ETL Dev, адрес `/python/`. Общий дизайн, пользователи и справочник
групп; отдельные задания, очередь, история и фоновый процесс. Redis и Celery не нужны.

## Установка на vm-dwh

В PowerShell **от имени администратора под DAICHI\ETLadmin**:

```powershell
cd C:\Users\ETLadmin\Desktop\TransferData
.\windows\Update-Portal.ps1
```

После сообщения об успешном обновлении:

```powershell
py -m transferdata.web setup_python_jobs --connection "DWH — назначение"
.\windows\Install-PythonWorker.ps1
```

Название подключения укажите как в разделе «1С Перенос данных → Подключения».
Нужна база `DataWH` на `vm-dwh`. Можно убрать `--connection`, если такое активное
подключение только одно. Настройки Windows-аутентификации, драйвера и доверия
сертификату берутся из этого подключения. Новые зависимости для первого задания
не нужны: pandas, tqdm и SQLAlchemy обработчик не использует.

Установщик один раз запросит пароль **Windows-учётной записи ETLadmin** через
системный диалог `Get-Credential`. Он регистрирует задачу `ETL Dev — Python` для
запуска при загрузке Windows независимо от входа пользователя и сразу запускает её.
Пароль не записывается в файлы проекта. Существующую одноимённую задачу установщик
не заменяет. Следующие обновления через `Update-Portal.ps1` обнаружат четвёртую
задачу, дождутся окончания обработки и восстановят прежнее состояние задач.

Если используете окружение `.venv`, вызывайте команды настройки через
`.\.venv\Scripts\python.exe -m transferdata.web ...`, тот же интерпретатор,
который выбирает `Start-Panel.ps1`.

## Первое задание: заголовки коммерческих предложений

Команда настройки создаёт задание **«Заголовки коммерческих предложений»** с
параметрами `{"date_from":"2023-01-01"}`. Повторный вызов не меняет существующее
задание. Запуск и расписание автоматически не включаются.

Откройте «Python обработчик → Задания», проверьте подключение и нажмите «Запустить».
В карточке результата видны число найденных и обработанных документов, число
записанных строк, полоса прогресса, статус и журнал. Они обновляются автоматически.
После проверки первого результата настройте время и периодичность — каждый день,
дни недели, день месяца — и включите расписание. Часовой пояс по умолчанию Москва.

Читаются таблицы `erp.[Документ.бит_КоммерческоеПредложениеКлиенту]` и
`erp.[Документы.бит_КоммерческоеПредложениеКлиентуТовары]`. Записываются только
`DocumentKey`, `NumberRow`, `Header` в существующую таблицу
`erp.[Документы.бит_КоммерческоеПредложениеКлиентуТоварыHeaders]`. Таблица должна
существовать, учётной записи нужны SELECT на источники и SELECT/DELETE/INSERT
на заголовки. Ограничение длины Header должно вмещать исходный текст.

Алгоритм сохраняет последний непустой заголовок по возрастанию номера строки.
NULL и пустая строка наследуют предыдущий заголовок; до первого заголовка остаётся
пустая строка. Текст с апострофами и кириллицей передаётся параметрами ODBC.

Документы, для которых заполнены все номера строк, пропускаются. Если хотя бы
одна строка отсутствует, заголовки **всего этого документа** заменяются в одной
транзакции. Это исправляет неполные документы после старого скрипта. Ошибка
отменяет текущий документ и завершает запуск с ошибкой; ранее успешно обработанные
документы остаются. Следующий ручной запуск продолжит с неполных документов.
Сессионная блокировка SQL Server защищает эту таблицу от одновременной обработки
другим экземпляром того же встроенного обработчика.

## Другие Python-файлы

1. Разместите свой доверенный `.py` файл на сервере в `.state\python-scripts`,
   например `.state\python-scripts\reports\daily.py`.
2. Создайте задание, выберите «Python-файл на сервере», укажите `reports/daily.py`.
3. Задайте JSON-параметры, ограничение времени, группу и расписание.
4. Проверьте ручной запуск; журнал содержит stdout/stderr и код завершения.

Файл выполняется отдельным процессом Python от имени Windows-учётной записи
обработчика, с её доступом к базам и файлам. Используется тот же интерпретатор,
которым запущен worker; необходимые для своего скрипта пакеты установите в него.
Рабочий каталог — корень TransferData. Пути вне каталога python-scripts и
ссылки на файлы за его пределами отклоняются. Пароли храните в окружении или
штатном хранилище секретов, а не в JSON-параметрах.

Пример чтения параметров:

```python
import json
import os

parameters = json.loads(os.environ.get("ETL_JOB_PARAMETERS", "{}"))
print("Обработка начата", flush=True)
# Ваш код. При ошибке выбрасывайте исключение или завершайте процесс ненулевым кодом.
print("Обработка завершена", flush=True)
```

Пользовательские скрипты должны сами задавать границы транзакций и печатать нужные
диагностические сообщения. У встроенного обработчика есть счётчик документов;
у произвольного файла по умолчанию отображаются статус, время и журнал, без
выдуманного процента выполнения. Последние 65 536 символов вывода сохраняются в истории.
Максимальное время ограничивает процесс, на Windows дерево дочерних процессов
удерживается в Job Object и завершается при остановке worker.

## Управление и диагностика

В списке есть поиск, фильтр групп с текстовым поиском, группировка карточек и
массовые операции: назначить группу, повторить, архивировать, восстановить, удалить.
Удаление сохраняет историю. Задания в очереди или выполняющиеся нельзя удалить
или архивировать. Для каждой подсистемы одновременно работает один worker;
повторная постановка уже активного задания возвращает имеющийся запуск.

Задача Windows должна иметь состояние **Running**, а не Ready. На странице обзора
есть индикатор связи с Python worker. Для диагностики в текущем окне:

```powershell
.\windows\Start-Panel.ps1 -Mode python-worker
```

Не запускайте второй экземпляр поверх задачи планировщика: блокировка этого
не позволит. После аварийного завершения незавершённый запуск помечается
«Прерван: проверьте результат» при следующем старте worker; автоматического
повторного выполнения такого запуска нет.

Для доступа сотрудникам выдайте Django-права приложения `python_jobs` на просмотр
заданий/запусков и, при необходимости, добавление, изменение и удаление заданий.
Запуск требует права изменения. Права на управление Python-задачами выдавайте
пользователям, которые должны запускать серверные скрипты.
