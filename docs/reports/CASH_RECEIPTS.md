# Перевод отчёта о денежных поступлениях

Назначение: `erp_ai.CashReceipts`, ReportDate — число `yyyyMMdd`.
Схема `erp_ai` и формат даты согласованы. Имя таблицы предложено, расписание пока
не задано. Исполняемый SQL и задание ещё не созданы: нужны метаданные конкретной
базы и состав параметров исходного отчёта. Физические `_Fld…`/`_Reference…` не угадываются.

## Логика исходного запроса

| Ветка | Источник | Регистратор | Сумма |
|---|---|---|---|
| Безналичные поступления | ДенежныеСредстваБезналичные | ПоступлениеБезналичныхДенежныхСредств | SUM(СуммаУпр) |
| Наличные поступления | ДенежныеСредстваНаличные | ПриходныйКассовыйОрдер | SUM(СуммаУпр) |
| Возвраты клиенту | бит_ОборотыПоБюджетам.Обороты | СписаниеБезналичныхДенежныхСредств / РасходныйКассовыйОрдер | SUM(СуммаУпрОборот) |

Ветки объединяются UNION ALL. Отбор возвратов использует значение перечисления
`ХозяйственныеОперации.ВозвратОплатыКлиенту`.

Для первых двух веток ЦФО берётся из левого соединения с
`бит_СоответствияАналитик` по подразделению. Вид соответствия — предопределённый
`бит_ВидыСоответствийАналитик.СтруктураПредприятия_ЦФО`.
`ЛеваяАналитика_2/3` и `ПраваяАналитика_2/3` должны быть НЕОПРЕДЕЛЕНО.
НЕОПРЕДЕЛЕНО нельзя автоматически заменить SQL NULL: для составных типов нужны
их фактические теги, типы и компоненты из метаданных.

После объединения выбирается MIN(ДатаВерсии) по регистратору. В исходнике
**INNER JOIN** к ВерсииОбъектов: документы без версии исключаются.
Поэтому запасное значение `ISNULL(ДатаВерсии, TransDate)` не возвращает строки,
у которых версий вообще нет. Заменять соединение на LEFT JOIN без решения
владельца отчёта нельзя.

## Что нужно сохранить при переводе

- У первых двух регистров нет явного отбора Активность. Самовольно добавлять его
  нельзя; это изменит исходный результат.
- Виртуальная таблица Обороты для бюджетного регистра требует отдельного
  воспроизведения активности, вида регистра, знака ресурса и периодичности
  Регистратор. Не добавлять минус ко всем возвратам по названию операции.
- Начальная дата отсутствует: запрос читает всю историю до ТекущаяДата.
- `AmountUSD` — псевдоним ресурса СуммаУпр, а не доказанная конвертация в USD.
  Валютных расчётов/курсов исходный запрос не содержит.
- В третьей ветке BankAccountKeyName возвращает ссылку, а не наименование, как
  первые две. Для SQL нужен единый тип; рекомендуем отдельные ссылку и название,
  после согласования конечного набора колонок.
- Ссылки регистратора, CFO, статьи и подразделения сохраняются вместе с типами
  составных ссылок. Представления документов — номер и дата; ссылки не заменять
  только текстом.
- Соединения должны учитывать коды типов, пустые ссылки и разделение данных.
- Соответствия аналитик могут быть неуникальны. Нельзя самовольно выбирать TOP 1
  или DISTINCT: это изменит суммы по сравнению с исходным отчётом.
- Даты 1С корректируются согласованным правилом: год < 3753 оставить,
  иначе DATEADD(year, -2000, поле). Границы виртуальной таблицы сверяются с 1С.

## Сбор метаданных на сервере

После обновления портала выполните под сервисной Windows-учётной записью:

```powershell
py -m transferdata.web export_onec_report_metadata --output .state\cash-receipts-metadata.json
```

Если активных источников несколько, добавьте `--connection "Название подключения"`.
Команда пакетно читает основные объекты, затем только нужные цепочки ссылок:
организация → префикс, контрагент → партнёр → наименование, счёт/касса.
В файле нет строк документов, паролей и строк подключения. Имена конфигурации,
структуры и значения перечислений присутствуют.

Рабочие задания, таблицы и сохранённые структуры портала не меняются.
При недоступном объекте экспортирует остальные структуры и добавляет запись
в `issues`. Файл с существующим именем не перезаписывается; задайте другое имя.
`--use-cache` разрешает актуальные сохранённые структуры вместо повторного чтения.

## Параметры, которых нет в тексте запроса

- ТекущаяДата: способ вычисления/граница периода.
- ДатаЧислом: подтверждён формат yyyyMMdd.
- СтатьиОборотов, СтатьиОборотовБюджет: полный состав списков.
- СтатьяGOODS, СтатьяWorks, СтатьяОборотовGOODS, СтатьяОборотовWorks.
- Ссылка предопределённого вида соответствия СтруктураПредприятия_ЦФО.

Названия Goods/Works не определяют конкретные записи базы. Нужно получить код
заполнения параметров или настройки исходного отчёта. UUID пользователю искать
вручную не требуется: можно начать с наименований и кода УстановитьПараметр.

Текст для 1С-разработчика:

> Для перевода запроса отчёта в SQL нужна подготовка параметров:
> СтатьиОборотов, СтатьиОборотовБюджет, СтатьяGOODS, СтатьяWorks,
> СтатьяОборотовGOODS, СтатьяОборотовWorks, ТекущаяДата и ДатаЧислом.
> Пришлите фрагмент модуля с УстановитьПараметр и заполнением списков, включая
> поиск ссылок по коду/предопределённому имени. Также нужен способ получения
> СтруктураПредприятия_ЦФО. Код выполнения запроса уже есть.

## Сверка перед расписанием

Для фиксированной ТекущаяДата сравниваются строки/суммы по каждой из трёх веток,
регистратору, статье и ЦФО; документы без версий и возвраты проверяются отдельно.
После совпадения — полный перенос в новую таблицу и согласованное расписание.
