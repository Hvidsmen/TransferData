# Перевод отчёта о денежных поступлениях

Назначение: `erp_ai.CashReceipts`, ReportDate — число `yyyyMMdd`.
Генератор и команда создания задания готовы. Используются подтверждённые статьи
в обоих наборах (ДДС и бюджет):

| Код | Категория |
|---|---|
| 00-000012 | Goods |
| 00-000014 | Works, включая исторические движения «НЕ ИСПОЛЬЗОВАТЬ…» |
| 00-000017 | OCM |

CN, дополнительные скидки и остальные статьи исключены. Вид соответствия
выбирается по точному коду `СтруктураПредприятия_ЦФО`. По умолчанию область данных — 0.
Ссылки берутся из ранее выгруженного CSV и повторно проверяются в исходной базе.

## Создать выгрузку на сервере

В PowerShell от имени администратора под сервисной учётной записью:

```powershell
cd C:\Users\ETLadmin\Desktop\TransferData
.\windows\Update-Portal.ps1
if ($LASTEXITCODE -ne 0) { throw "Обновление не завершено" }
py -m transferdata.web prepare_cash_receipts_report --create-job
```

Нужны ранее полученные файлы `.state\cash-receipts-metadata.json` и
`.state\cash-receipts-choices.csv`. Команда сама перечитывает роли измерений
и ресурсов бюджета обновлённым помощником. Повторно присылать файлы не требуется.
Если имена файлов другие, укажите `--metadata` и `--choices`.
Если назначений несколько, добавьте `--target-connection "DWH — назначение"`.

Команда проверяет выбранные ссылки/коды в источнике, просит SQL Server описать
результат SELECT без исполнения выгрузки, сохраняет `.state\CashReceipts.sql`
и создаёт задание **«Денежные поступления»** в разделе **«1С Перенос данных»**.
Расписание выключено. Первый запуск — кнопкой «Запустить» в портале.
Назначение должно содержать схему `erp_ai`; таблица `CashReceipts` создаётся
загрузчиком при первом запуске. Нужны права создания таблиц и записи в эту схему.
Полная загрузка использует промежуточную таблицу и атомарную публикацию.

Для подготовки только SQL без задания уберите `--create-job`.
Существующие SQL-файлы и задания назначения не перезаписываются. Для повторного
экспорта SQL задайте другое имя `--output .state\CashReceipts-v2.sql`.

ТекущаяДата вычисляется в Москве на момент запроса; ReportDate — число yyyyMMdd.
Источник читается за всю историю. Сначала сравните количество строк и суммы
по Goods/Works/OCM с 1С за одинаковую дату, затем задайте расписание в портале.
Статическая проверка SELECT подтверждает структуру, но не равенство сумм отчёту 1С.

Представление документа — номер и дата. Поля `…Ссылка` сохраняют физические
идентификаторы; типы составных ссылок сохраняются отдельно. `CFO` содержит
наименование для ссылки на `Справочник.Подразделения`; для неожиданного типа
представление пустое, все компоненты составного значения сохраняются.
В третьей ветке счёт/касса приводятся к наименованию, как в первых двух;
исходная ссылка сохраняется в `BankAccountСсылка` и в ключе группировки. В первых
двух ветках это поле NULL: исходник группирует их только по наименованию счёта.

## Логика исходного запроса

| Ветка | Источник | Регистратор | Сумма |
|---|---|---|---|
| Безналичные поступления | ДенежныеСредстваБезналичные | ПоступлениеБезналичныхДенежныхСредств | SUM(СуммаУпр) |
| Наличные поступления | ДенежныеСредстваНаличные | ПриходныйКассовыйОрдер | SUM(СуммаУпр) |
| Возвраты клиенту | бит_ОборотыПоБюджетам.Обороты | СписаниеБезналичныхДенежныхСредств / РасходныйКассовыйОрдер | SUM(СуммаУпрОборот) |

Ветки объединяются UNION ALL. Отбор возвратов использует значение перечисления
`ХозяйственныеОперации.ВозвратОплатыКлиенту`.

Для первых двух веток ЦФО берётся из левого соединения с
`бит_СоответствияАналитик` по подразделению. Вид соответствия — предопределённый
`бит_ВидыСоответствийАналитик.СтруктураПредприятия_ЦФО`.
`ЛеваяАналитика_2/3` и `ПраваяАналитика_2/3` должны быть НЕОПРЕДЕЛЕНО.
НЕОПРЕДЕЛЕНО нельзя автоматически заменить SQL NULL: для составных типов нужны
их фактические теги, типы и компоненты из метаданных.

После объединения выбирается MIN(ДатаВерсии) по регистратору. В исходнике
**INNER JOIN** к ВерсииОбъектов: документы без версии исключаются.
Поэтому запасное значение `ISNULL(ДатаВерсии, TransDate)` не возвращает строки,
у которых версий вообще нет. Заменять соединение на LEFT JOIN без решения
владельца отчёта нельзя.

## Что нужно сохранить при переводе

- У первых двух регистров нет явного отбора Активность. Самовольно добавлять его
  нельзя; это изменит исходный результат.
- Виртуальная таблица Обороты для бюджетного регистра требует отдельного
  воспроизведения активности, вида регистра, знака ресурса и периодичности
  Регистратор. Не добавлять минус ко всем возвратам по названию операции.
- Начальная дата отсутствует: запрос читает всю историю до ТекущаяДата.
- `AmountUSD` — псевдоним ресурса СуммаУпр, а не доказанная конвертация в USD.
  Валютных расчётов/курсов исходный запрос не содержит.
- В третьей ветке BankAccountKeyName возвращает ссылку, а не наименование, как
  первые две. Для SQL нужен единый тип; рекомендуем отдельные ссылку и название,
  после согласования конечного набора колонок.
- Ссылки регистратора, CFO, статьи и подразделения сохраняются вместе с типами
  составных ссылок. Представления документов — номер и дата; ссылки не заменять
  только текстом.
- Соединения должны учитывать коды типов, пустые ссылки и разделение данных.
- Соответствия аналитик могут быть неуникальны. Нельзя самовольно выбирать TOP 1
  или DISTINCT: это изменит суммы по сравнению с исходным отчётом.
- Даты 1С корректируются согласованным правилом: год < 3753 оставить,
  иначе DATEADD(year, -2000, поле). Границы виртуальной таблицы сверяются с 1С.

## Сбор метаданных на сервере

После обновления портала выполните под сервисной Windows-учётной записью:

```powershell
py -m transferdata.web export_onec_report_metadata --output .state\cash-receipts-metadata.json
```

Если активных источников несколько, добавьте `--connection "Название подключения"`.
Команда пакетно читает основные объекты, затем только нужные цепочки ссылок:
организация → префикс, контрагент → партнёр → наименование, счёт/касса.
В файле нет строк документов, паролей и строк подключения. Имена конфигурации,
структуры и значения перечислений присутствуют.

Рабочие задания, таблицы и сохранённые структуры портала не меняются.
При недоступном объекте экспортирует остальные структуры и добавляет запись
в `issues`. Файл с существующим именем не перезаписывается; задайте другое имя.
`--use-cache` разрешает актуальные сохранённые структуры вместо повторного чтения.

## Сверка перед расписанием

Для фиксированной ТекущаяДата сравниваются строки/суммы по каждой из трёх веток,
регистратору, статье и ЦФО; документы без версий и возвраты проверяются отдельно.
После совпадения — полный перенос в новую таблицу и согласованное расписание.

## Выбор статей без 1С-разработчика

Теперь можно получить читаемый список из ERP, не зная UUID:

```powershell
py -m transferdata.web export_cash_receipts_choices
```

Команда создаёт `.state\cash-receipts-choices.csv` (UTF-8 BOM, разделитель `;`,
открывается в Excel). В списке три набора: статьи ДДС, статьи оборотов бюджета,
виды соответствия аналитик. Колонки: код, наименование, число движений/соответствий,
область данных, исходная ссылка и пустые поля выбора.

Для текущего согласованного отчёта поля `ВключитьВОтчет` и `Категория`
заполнять не нужно: команда подготовки выбирает ровно три кода из начала этой
инструкции в области 0 и проверяет их ссылки в источнике. Остальные строки CSV
не влияют на выгрузку. Другие наборы статей требуют отдельного изменения настроек.

Число записей — ориентир для выбора, а не итог финансового отчёта. Оно считается
до отборов списка статей и соединения с версиями. У ДДС учитываются два вида
документов поступления; исходный запрос не фильтрует их активность. Для бюджета
учитываются активные движения возврата клиенту по двум видам расходных документов.
Суммы/контрагенты/номера документов в файл не выгружаются. Отсутствующие в каталоге,
но использованные ссылки сохраняются с пометкой. Неиспользованные статьи тоже
показываются; пометка удаления не скрывает исторически использованные записи.

Чтение выполняется только SELECT под сервисной Windows-учётной записью. Задания
и структуры портала не изменяются. Пароли и строки подключения не выводятся.
Формулы из наименований экранируются для безопасного открытия CSV в Excel.

Подсчёт читает регистры за всю историю до текущего момента по Москве и может
занять несколько минут. Для быстрого списка без подсчёта:

```powershell
py -m transferdata.web export_cash_receipts_choices --no-counts
```

Если активных источников несколько, добавьте `--connection "Название подключения"`.
`--as-of 2026-10-23T18:00:00` задаёт точную границу по Москве;
`--timeout 600` увеличивает таймаут одного SQL-запроса.
Существующий файл не перезаписывается — можно задать новое имя через `--output`.
Разделители и имена берутся из свежих метаданных. Для нескольких разделителей
данных или несовпадающих разделителей экспорт прерывается, чтобы не смешать области.
