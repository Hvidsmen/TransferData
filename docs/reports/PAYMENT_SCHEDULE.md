# График платежей по дням, две готовые суммы

Назначение по умолчанию — `erp_ai.PaymentScheduleReport` в DWH (SQL Server).
Выгружается **вся история и будущие платежи**, поле `Период` рассчитывается по дням.

Два основных денежных поля:

| Столбец | Источник |
|---|---|
| `Сумма` | Оборот ресурса `СуммаПлатежа` в валюте платежа |
| `USD` | Оборот готового ресурса суммы управленческого учёта |

Владелец подтвердил, что управленческая валюта — USD. Курсы валют не читаются,
пересчёта валют и дополнительного округления нет. Для `USD` автоматически
выбирается единственный ресурс `СуммаУпр` или `СуммаПлатежаУпр`. Если конфигурация
использует другое имя, задайте `--usd-resource "ТочноеИмяРесурса"`.
При отсутствии отдельного готового ресурса команда остановится и покажет
реальные ресурсы регистра. Подстановка исходной суммы вместо управленческой
не выполняется.

## Подготовка на vm-dwh

PowerShell **от имени администратора под сервисной учётной записью**:

```powershell
cd C:\Users\ETLadmin\Desktop\TransferData
.\windows\Update-Portal.ps1
```

После успешного обновления создайте задание:

```powershell
py -m transferdata.web prepare_payment_schedule_report --connection "ERP — источник" --target-connection "DWH — назначение" --create-job
```

Команда сама прочитает метаданные регистра, табличную часть реестра, структуру
заказа и инвойса. Обновление пересобирает установленный помощник 1С; пересылать
файлы метаданных не нужно. Физические `_Fld…`, `_Document…`, коды типов ссылок
и значения перечислений берутся из конфигурации базы.

Результат — SQL-файл `.state\PaymentScheduleReport.sql` и задание
**«График платежей · по дням · USD»** в «1С Перенос данных → Задания».
Расписание выключено. Первый запуск выполните вручную и сравните суммы и статусы
с 1С. Затем задайте расписание в карточке задания.

Таблица создаётся штатным загрузчиком при первом запуске. Схема `erp_ai` должна
существовать и быть доступна на запись. Для другого назначения доступны
`--target-schema`, `--target-table`; для другого SQL-файла — `--output`.
Существующие файлы и задания с тем же назначением не перезаписываются.

Если имя управленческого ресурса неизвестно:

```powershell
py -m transferdata.web prepare_payment_schedule_report --connection "ERP — источник" --inspect
```

Команда покажет поля с пометками «ресурс»/«измерение» и табличные части реестра.
Источник, задания и DWH при этом не изменяются.
Для подготовки только SQL уберите `--create-job`.
Если используется `.venv`, вызывайте команды через `.\.venv\Scripts\python.exe`
вместо `py`, как при настройке остальных заданий портала.

## Логика отчёта

- Дневные обороты рассчитываются по всем измерениям регистра, включая
  разделители данных. Учитывается активность. Для регистра остатков учитывается
  знак вида движения, для оборотного регистра дополнительный минус не добавляется.
- Исключаются группы с нулевыми оборотами всех ресурсов. Дополнительной
  группировки по неделям/месяцам нет.
- Статусы: «Факт», «Заявка в реестре», «План (Заявка создана)»,
  «План (Заявка не создана)». Для реестра проверяется `Проведен`.
- Проверка через `EXISTS` воспроизводит исходный DISTINCT заявок: несколько
  строк или реестров не увеличивают суммы.
- Ссылки сохраняются в `…Ссылка`, типы — в `…Тип`. Добавляются наименования,
  а у документов — `…Дата` и `…Номер`. Перечисления выводятся по именам из метаданных.
- `ВалютаПлатежа` сохраняется рядом с `Сумма`, `ВалютаUSD` содержит USD.
- `СуммаИнвойса` — отдельная исходная сумма документа из присланного запроса.
- Даты корректируются согласованным правилом: год < 3753 оставить, иначе -2000 лет.
  `ДатаКурса` сохраняется как реквизит и не участвует в расчёте денежных сумм.
- Соединения учитывают разделители данных. Явно общие справочники без разделителей
  соединяются как глобальные. Несовместимая структура вызывает понятную ошибку.

`ВЫБРАТЬ РАЗРЕШЕННЫЕ` относится к правам пользователя 1С. Прямой SQL выполняется
под SQL/Windows-учётной записью подключения и автоматически не воспроизводит RLS 1С.
Блоки `{ВЫБРАТЬ …}` и `{ГДЕ …}` — настройки СКД; динамические отборы, не переданные
в исходных условиях выгрузки, не добавляются. Перед расписанием сверяйте строки,
статусы и обе суммы с 1С на одинаковых отборах.
