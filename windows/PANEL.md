# Django-панель на vm-dwh: 0.0.0.0:8003

Панель на Django admin: вход по логину/паролю, формы подключений и заданий,
cron и часовой пояс, очередь действий, история с количеством строк и длительностью.
Перенос выполняет отдельный worker. Redis, Celery и отдельная БД панели не нужны:
очередь, задания и история хранятся в SQLite `.state/panel.sqlite3`.

## Обновление существующей установки

Под Windows-пользователем `DAICHI\ETLadmin`, в папке проекта:

```powershell
git pull origin main
py -m pip install --user --no-build-isolation .
py -m transferdata.web migrate
py -m transferdata.web collectstatic --noinput
py -m transferdata.web createsuperuser
py -m transferdata.web import_config config.json
```

Введите новый логин и пароль администратора панели в интерактивном запросе.
Это отдельная учётная запись, не пароль SQL Server/PostgreSQL.
Импорт выполняется один раз: существующие подключения/задания не перезаписываются.
Он сохраняет маппинг всех столбцов, TLS-настройки и cron из рабочего JSON.
Пароли в SQLite не копируются. Расписание импортированных заданий выключено.
Файлы с BOM поддерживаются; испорченную ранее кириллицу импорт не исправляет.

Если `git pull` сообщает локальные изменения в `windows/Run-Transfer.ps1`,
не сбрасывайте их: текущая версия панели этот файл не меняет. Сохраните локальную
копию и проверьте, какая версия конфликтует, прежде чем продолжать обновление.

Для установки через uv вместо пользовательского Python: `py -m uv sync --locked`,
затем заменяйте `py` в командах подготовки на `.\.venv\Scripts\python.exe`.
Не смешивайте окружения для миграций, сбора статики, создания пользователя и сервера.

## Запуск двух процессов

В первом PowerShell:

```powershell
.\windows\Start-Panel.ps1 -Mode web
```

Во втором PowerShell, под тем же Windows-пользователем:

```powershell
.\windows\Start-Panel.ps1 -Mode worker
```

Веб-сервер Waitress слушает `0.0.0.0:8003`. Открывайте в браузере
`http://vm-dwh:8003` или `http://192.168.221.178:8003`.
`0.0.0.0` — адрес привязки, а не адрес для браузера.
Другие DNS-имена/IP добавьте параметром `-AllowedHosts` (список через запятую).
При необходимости разрешите входящий TCP 8003 в Windows Firewall только из
нужной внутренней сети. Для доступа вне доверенной сети используйте HTTPS
через корпоративный reverse proxy; HTTP сам по себе не шифрует пароль панели.
При HTTPS задайте `TRANSFERDATA_HTTPS=1` и нужные origin через
`TRANSFERDATA_CSRF_ORIGINS`, например `https://etl.company.local`.

Worker загружает существующий `.state/postgres.credential.xml`, передаёт
TARGET_USER/TARGET_PASSWORD только в своё окружение и входит в SQL Server
от имени Windows-пользователя процесса. DPAPI-файл должен принадлежать этому
пользователю на этой машине. Для других имён переменных/других паролей задайте
соответствующие переменные в окружении worker отдельно.

## Работа в браузере

1. Войдите созданным администратором. Импортированное подключение уже доступно.
2. Откройте «Задания» → `contractors`. Проверьте источник, цель и маппинг.
3. В списке заданий выделите строку, выберите «Проверить подключения» и «Выполнить».
4. Откройте «История запусков» и обновите страницу. После обработки worker статус
   станет «Успешно» или «Ошибка».
5. Действие «Получить структуру источника» показывает список таблиц выбранной схемы
   и столбцы текущей таблицы в поле «Структура источника» результата. После него
   обновите форму задания: у имени таблицы появятся подсказки, а в редакторе
   столбцов заработает «Заполнить из полученной структуры». Длинным именам
   назначаются короткие имена, которые можно изменить перед сохранением.
   Новое задание создаётся через «Добавить».
6. Для новой таблицы используйте «Создать целевую таблицу». Для переноса —
   «Запустить полную загрузку». Оба действия требуют подтверждения в панели.
7. Отключите прежнюю ежедневную задачу Windows или CLI `serve`, прежде чем включать
   расписание в панели. Затем включите «Включить расписание» в задании и сохраните.
   Пустое «Следующий запуск» заполнится worker в течение нескольких секунд.

Маппинг редактируется парами полей в форме задания; JSON доступен в раскрываемом
разделе. Пустой объект означает все исходные столбцы. Для переноса части столбцов
задайте только нужные пары. Для длинных имён
PostgreSQL нужны короткие имена назначения, как в вашем импортированном config.json.
Полная замена и откат используют тот же ETL-код, который перенёс 86 830 строк.

## Постоянная работа

Создайте две задачи Windows «При запуске компьютера» под `DAICHI\ETLadmin`:

```text
powershell.exe -NoProfile -NonInteractive -File "C:\Users\ETLadmin\Desktop\TransferData\windows\Start-Panel.ps1" -Mode web
powershell.exe -NoProfile -NonInteractive -File "C:\Users\ETLadmin\Desktop\TransferData\windows\Start-Panel.ps1" -Mode worker
```

В поле программы укажите `powershell.exe`, остальное — в аргументах. Рабочая папка —
каталог проекта. Запускать независимо от входа пользователя, с сохранением пароля,
не S4U. Включите перезапуск при сбое и выключите ограничение времени выполнения.
Не допускайте второго экземпляра. Старую задачу разовой ежедневной загрузки отключите.
Windows-пользователю требуется право пакетного входа, доступ к исходной БД и DPAPI.

Панель доступна и без worker, но очередь тогда не выполняется. Автообновления
страниц и оповещений нет — обновляйте историю вручную. Расписание переживает
перезапуск; просроченные запуски объединяются в один, без накопления за каждый день.
Очередь одного задания не допускает дублирования, worker выполняет задания последовательно.
При остановке worker посреди загрузки результат помечается «Прерван» при следующем
старте: транзакция могла успеть зафиксироваться, поэтому проверьте цель перед повтором.
Автоматического повторения таких запусков нет. Изменения задания не меняют уже
поставленное в очередь действие: оно хранит снимок настроек на момент постановки.

Резервируйте каталог `.state` при остановленных web/worker. В нём находятся SQLite,
секретный ключ Django и DPAPI-файл. Ограничьте NTFS-доступ учётной записью сервиса
и администраторами. DPAPI нельзя просто перенести на другой компьютер.
